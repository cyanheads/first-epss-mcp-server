## Overview

Daily exploitation forecasts from [FIRST EPSS](https://www.first.org/epss/), published by FIRST and generated by Empirical Security. Look up CVE scores, inspect historical movement, discover candidates, and combine likelihood with caller-supplied CVSS severity. The [public API](https://api.first.org/epss/) needs no key or registration; EPSS estimates observed exploitation within the next 30 days.

### Tools

| Tool | Description |
|:---|:---|
| `epss_get_scores` | Fetch current or historical EPSS probability and percentile for supplied CVEs |
| `epss_get_timeseries` | Inspect daily history, exact-date changes, peaks, gaps, and model transitions |
| `epss_query_threshold` | Discover CVEs by inclusive score bounds, CVE year, or recent dataset addition |
| `epss_prioritize_cves` | Assign configurable remediation tiers using EPSS and caller-supplied CVSS severity |
| `epss_list_reference` | Explain score interpretation, models, coverage, and prioritization conventions |

## Capability reference

### `epss_get_scores` <sub>tool</sub>

- Submit up to 5,000 CVEs; the first 500 unique identifiers are processed. `cves` accepts an array or comma/newline-delimited string, with case and surrounding whitespace normalized
- Optional `date` selects a UTC snapshot from `2021-04-14` through today; omitted or blank means latest available. Results include probability, percentile, score date, and model attribution, ordered by EPSS descending then CVE
- `unscoredCves` distinguishes `invalid_format` from `not_returned`; `deferredCves` lists identifiers beyond the workload cap for a follow-up call

---

### `epss_get_timeseries` <sub>tool</sub>

- Same CVE/date inputs, with up to 5,000 submitted entries and the first 50 unique identifiers processed; resubmit `deferredCves` separately
- Each item has an anchor `current`, up to 30 preceding daily observations in `series`, `missingDates`, and the observed peak. `delta7d` and `delta30d` require exact calendar baselines; unavailable comparisons are explicit
- `modelBoundariesCrossed` and per-comparison flags disclose methodology changes without attributing score movement to new exploitation evidence

---

### `epss_query_threshold` <sub>tool</sub>

- Inclusive `minEpss` / `maxEpss` and `minPercentile` / `maxPercentile` bounds intersect with `year`, `addedWithinDays`, and optional historical `date`; at least one bound, year, or addition filter is required. `addedWithinDays` measures dataset addition relative to upstream present, independently of `date`
- `limit` is 1–10,000 candidates (default 100), with `offset` pagination and EPSS descending order. With `year`, `candidateTotal` counts broad-query candidates and `total` is `null` / `totalRelation: "unknown"`; without it, `total` is exact
- An empty year-filtered page can still have `hasMore: true`. Continue with identical filters and limit, the returned `provenance.scoreDates[0]` as `date`, and `nextOffset` as `offset`

---

### `epss_prioritize_cves` <sub>tool</sub>

- Submit up to 5,000 `{ cve, cvssBaseScore? }` entries; the first 500 unique CVEs are processed using latest available EPSS. CVSS is caller-supplied, 0–10; conflicting values for a duplicate CVE are rejected
- Defaults: `severityThreshold: 7` and `likelihood: { metric: "epss", threshold: 0.10 }`, both inclusive. Select `metric: "percentile"` explicitly to use rank; thresholds are configurable policy conventions
- Known scores/severity enter `act_now` (high/high), `scheduled` (high/low), `monitor` (low/high), or `defer` (low/low). Missing severity stays in `epssOnly`; missing EPSS stays in `unscoredCves`. Resubmit `deferredCves` with original severity and policy settings

---

### `epss_list_reference` <sub>tool</sub>

- `topic`: `interpretation`, `models`, `coverage`, `prioritization`, or `all` (default)
- Static guidance includes primary-source links and a `verifiedAt` date; works without an upstream request

## Features

Built on [`@cyanheads/mcp-ts-core`](https://github.com/cyanheads/mcp-ts-core): stdio and Streamable HTTP transports, pluggable auth (`none` / `jwt` / `oauth`), swappable storage (`in-memory`, `filesystem`, `Supabase`, `Cloudflare KV/R2/D1`), structured logging with optional OpenTelemetry tracing.

FIRST EPSS-specific:

- Keyless lookup against FIRST's public API, with bounded batches rather than corpus synchronization
- Shared API request pacing, transient-failure retries, cancellation, and a 45-second whole-call deadline
- Model attribution from a matching daily CSV header or, for explicitly dated requests, the published model schedule; verification failures remain visible
- Configurable severity/likelihood tiers, preserving the distinction between probability, percentile rank, and environment-specific risk

Agent-friendly output:

- Provenance: API source, retrieval time, score dates, and model metadata marked `verified`, `inferred`, or `unavailable`
- Explicit coverage: missing EPSS and CVSS remain unknown; `unscoredCves` and `deferredCves` distinguish omissions from work not queried. Transport failures fail the call
- Structured results and formatted text carry the same accounting, history gaps, pagination, thresholds, and recovery guidance

## Getting started

Add the following to your MCP client configuration file.

```json
{
  "mcpServers": {
    "first-epss-mcp-server": {
      "type": "stdio",
      "command": "bunx",
      "args": ["@cyanheads/first-epss-mcp-server@latest"],
      "env": {
        "MCP_TRANSPORT_TYPE": "stdio",
        "MCP_LOG_LEVEL": "info"
      }
    }
  }
}
```

Or with npx (no Bun required):

```json
{
  "mcpServers": {
    "first-epss-mcp-server": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@cyanheads/first-epss-mcp-server@latest"],
      "env": {
        "MCP_TRANSPORT_TYPE": "stdio",
        "MCP_LOG_LEVEL": "info"
      }
    }
  }
}
```

Or with Docker:

```json
{
  "mcpServers": {
    "first-epss-mcp-server": {
      "type": "stdio",
      "command": "docker",
      "args": ["run", "-i", "--rm", "-e", "MCP_TRANSPORT_TYPE=stdio", "ghcr.io/cyanheads/first-epss-mcp-server:latest"]
    }
  }
}
```

For Streamable HTTP, set the transport and start the server:

```sh
MCP_TRANSPORT_TYPE=http MCP_HTTP_PORT=3010 bun run start:http
# Server listens at http://localhost:3010/mcp
```

### Prerequisites

- [Bun v1.4.0](https://bun.sh/) or higher (or Node.js v24+).
- Internet access to FIRST's public EPSS API; no API key or account is required.

### Installation

1. **Clone the repository:**

```sh
git clone https://github.com/cyanheads/first-epss-mcp-server.git
```

2. **Navigate into the directory:**

```sh
cd first-epss-mcp-server
```

3. **Install dependencies:**

```sh
bun install
```

4. **Configure environment:**

```sh
cp .env.example .env
# Optional: edit framework transport, auth, logging, and telemetry settings
```

## Configuration

No server-specific settings are required.

| Variable | Description | Default |
|:---|:---|:---|
| `MCP_TRANSPORT_TYPE` | Transport: `stdio` or `http`. | `stdio` |
| `MCP_HTTP_HOST` | HTTP bind address. | `127.0.0.1` |
| `MCP_HTTP_PORT` | HTTP server port. | `3010` |
| `MCP_HTTP_ENDPOINT_PATH` | HTTP MCP endpoint path. | `/mcp` |
| `MCP_SESSION_MODE` | HTTP session mode: `stateless`, `stateful`, or `auto`. | `auto`; `.env.example` and Docker select `stateless` |
| `MCP_AUTH_MODE` | Authentication: `none`, `jwt`, or `oauth`. | `none` |
| `MCP_LOG_LEVEL` | Log level (`debug`, `info`, `warning`, `error`, etc.). | `debug`; client examples and Docker select `info` |
| `LOGS_DIR` | Directory for log files (Node.js only). | `<app-root>/logs` |
| `STORAGE_PROVIDER_TYPE` | Storage backend: `in-memory`, `filesystem`, `supabase`, `cloudflare-kv/r2/d1`. | `in-memory` |
| `OTEL_ENABLED` | Enable [OpenTelemetry](https://github.com/cyanheads/mcp-ts-core/tree/main/docs/telemetry). | `false` |

See [`.env.example`](./.env.example) for every server setting and the common framework overrides.

## Running the server

### Local development

- **Build and run the production version**:

  ```sh
  # One-time build
  bun run rebuild

  # Run the built server
  bun run start:http
  # or
  bun run start:stdio
  ```

- **Run checks and tests**:
  ```sh
  bun run devcheck  # Lints, formats, type-checks, and more
  bun run test      # Runs the test suite
  ```

## Development guide

See [`CLAUDE.md`](./CLAUDE.md) for development guidelines and architectural rules. The short version:

- Handlers throw, framework catches — no `try/catch` in tool logic
- Use `ctx.log` for logging, `ctx.state` for storage
- Register new tools and resources in the `createApp()` arrays in `src/index.ts`
- Wrap external API calls: validate raw → normalize to domain type → return output schema; never fabricate missing fields
